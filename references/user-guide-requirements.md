# End-User Guide Requirements

The user guide is for people who operate or benefit from the project without maintaining its internal implementation.

## Required sections

1. What this tool or workflow does
2. Who should use it and when not to use it
3. Before you begin
4. Primary workflow
5. Expected results and visible success state
6. Common tasks
7. Simplified troubleshooting
8. What users should not change
9. Getting help and information to collect
10. Quick reference

## Content rules

- Use plain language and short procedural steps.
- Put the normal path before exceptions.
- State required inputs and access.
- Explain where outputs appear and how to confirm success.
- Provide only actions that are safe for the documented user role.
- State when to stop retrying.
- Include request, run, record, or correlation identifiers when users can access them.
- Do not expose credentials, connector configuration, production internals, or destructive recovery procedures.
- Preserve limitations that affect user expectations.
